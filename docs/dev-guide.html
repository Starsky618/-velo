看这张图你能直接看到三件事

  1. 两条路在 ParseResult 处汇合 / 不重复strava 拉数据 + parsing 翻译 + activity 入库 / 各干一件事 / 串联非重复。

用"逆向"定义每个模块

默认只看"砍了会丢什么"（红框）/ 点击卡片再看"干一件事"+"边界规则"

app/strava/
砍了会丢什么用户没法绑 Strava / GPX 上传不受影响
干一件事第三方数据搬运：OAuth 授权 + webhook 监听 + 历史补传调度
边界规则只碰自己的 strava_imports / strava_tokens 表 / 拿到数据交给 parsing 翻译
app/parsing/
砍了会丢什么所有数据进不来 / 全瘫（GPX / Strava 都翻译不了）
干一件事各种源头数据 → 统一翻译成 ParseResult（纯计算 / 不碰 DB）
边界规则纯函数 / 不碰 DB / 不碰文件系统 / 接收参数返回结果
app/activity/
砍了会丢什么数据翻译完了没人组装入库 / 整套流瘫
干一件事骑行活动业务编排：调用 parsing + 入库 + 状态机 + 触发后续
边界规则唯一允许写 activities / trackpoints 表的模块 / 是 strava 的下游
app/segment/
砍了会丢什么数据有了但没人算"我第几名" / 排行榜消失
干一件事赛段定义和匹配 + 排行榜计算
边界规则activity 的下游 / 不能反向调 activity
app/user/
砍了会丢什么没法登录 / 没法看个人聚合数据
干一件事用户身份 + 个人统计（登录 / 资料 / 总览 / 热力图）
边界规则大部分主路径不依赖业务模块 / v5 例外 import activity 算 power-curve
app/notification/
砍了会丢什么骑完没人提醒"你刷新了 5km PR" / 用户少一份激励
干一件事检测值得通知的事件（PR / KOM / 朋友新骑）+ 推送
边界规则所有业务模块的下游 / 内部用 SAVEPOINT 隔离失败
app/admin/
砍了会丢什么没法在后台改数据 / 但小程序业务不受影响
干一件事管理后台反向控制（admin H5 所有 endpoint）
边界规则独立 router + 独立权限校验 / 不允许越过应用层直改 DB
app/monitor/
砍了会丢什么出问题没人喊 / 但业务不受影响
干一件事系统健康探针 + 告警通道
边界规则log-only 模式 / 不接通飞书（D 决策已记 memory）
app/middleware/
砍了会丢什么恶意刷 API 无防护 / 但本地能跑
干一件事全局拦截器（限流 / 请求日志 / CORS）
边界规则应用最外层 / 不碰业务逻辑
app/storage/
砍了会丢什么上传文件没法落地
干一件事GPX 文件系统读写（上传文件存哪 / 怎么读）
边界规则物理存储抽象 / 未来换 OSS 时只改这
app/agent/
砍了会丢什么curation / 未来 coach 没法调 LLM / 主业务不受影响
干一件事LLM 接入层（DeepSeek / OpenAI client 包装）
边界规则所有 LLM 调用集中在这 / 不允许其他模块直连
app/common/
砍了会丢什么小工具重复实现 / 不致命
干一件事跨模块共享小工具（geo 计算 / 不归任一模块独占）
边界规则克制 / 只放真共享的 / 别变垃圾桶

用这页能秒答的判断层问题

  1. "这个新功能该建在哪个模块？" — 看它砍了影响什么 / 影响和哪个模块逆向一致
  2. "AI 想让 A 调 B / 行不行？" — 点开看 B 的"边界规则" / 反向调 = 红线
  3. "两个模块功能像 / 是不是重复了？" — 点开看"干一件事" / 描述不同 = 不重复 / 一样 = 重构信号

假如要接 Garmin / igpsport / sellin · 该改哪 / 不改哪

不是真做 / 是给你看"扩展时判断层操作长啥样"

✓ 0 行新代码 · 直接复用 GPX 上传链路

典型场景：Garmin Connect 导出 .fit / iGPSport 导出 .gpx / sellin 导出 .gpx / 用户在他们平台下载文件 → 在 velo 点上传 → 选这个文件 → 完事。

✕ 不需要改的

  • parsing/ — fit_parser / gpx_parser 已覆盖
  • activity/ — 上传链路已支持
  • postgres schema — ParseResult 已兼容所有源
  • 前端 — upload 页已支持选文件

✓ 全 reusable

  • 全链路开箱即用
  • 用户体验路径：选文件 → 点上传
  • 判断层零成本 / 翻译层零成本
⚠ 需要 2 件事 · 但 80% reusable

典型场景：iGPSport / sellin / Garmin Connect 提供 OAuth API / 用户授权后我们自动同步（仿 Strava 模式）。

✱ 需要新建的

  • app/garmin/ 模块（仿 strava 结构）
    —— OAuth + webhook（如果对方支持）+ 同步调度 + worker
  • parsing/garmin_adapter.py（仿 strava_adapter）
    —— 把对方 API 返回的 JSON → ParseResult
  • 2 张 DB 表：garmin_imports + garmin_tokens（仿 strava 表结构）
  • 前端：profile 加"绑定 Garmin"按钮

✓ 全 reusable / 不动

  • parsing/coord_normalizer — 纠偏统一处理
  • activity/save_parse_result — 入库共享函数
  • activity / segment / notification — 下游全自动跑
  • postgres activities/trackpoints schema — 0 改
  • 所有展示前端（detail / explore / honor）

这个沙盘想让你看到的事

  1. 架构 trade-off 当年付得值 — 当时多花时间把"翻译"和"搬运"分开 / 今天扩展时省下来。
  2. 未来你拍"接哪个数据源"是判断层决策 — 用户量 / 集成成本 / 数据完整度 / 都是产品判断。技术成本固定 = 加一个翻译官 + 可选加一个搬运模块。
  3. 反例 — Persona Engine 当时跟 activity 混在一起 / 砍的时候连根拔起 / 5 stage 才清完。每加一个新模块都该问："砍它能不能干净？"

判断层 trigger 清单 · 你"安心不懂剩下的"机制

命中任一红色 trigger = 停下叫 Tim / 没命中 = 放心交 AI

怎么用：review AI 写的 diff 时打开浏览器对照查 / 不用记 / 每月 review 一次清单本身 / 新踩到的坑加进来 / 老 trigger 失效划掉 / 让清单跟项目一起进化。

# ADR-007: 为什么管理员赛段建设用贡献者众包,不用算法自动生成

## 状态
accepted (2026-04-22)

## 上下文

velo 的赛段(segments)系统是核心产品能力之一:用户上传骑行 → 系统自动匹配到已有赛段 → 进入排行榜 → 成为社交货币。

关键问题: **赛段从哪里来**?

v1-v4 现状: 赛段全部由 Tim 一人手动通过 `POST /api/segments` admin 接口创建。目前只有太原本地约 10 条赛段,无法支撑一线城市用户。

v5 规划期(2026-04)的赛段扩展策略讨论,有三个选项:

- **方案 A: 算法自动生成**。聚类分析大量骑行轨迹,识别"多人经常骑的路段"自动创建赛段。
- **方案 B: 管理员手动创建**。Tim 一人通过 admin 工具持续扩展。
- **方案 C: 贡献者众包 + 管理员审核**。各城市骨干骑手作为"区域赛段编辑员"提交赛段,Tim 审核后发布。

## 决策

velo 采用 **方案 C: 管理员手动创建 + 贡献者众包协助**。**不使用算法自动生成**。

实现路径:
- **短期(v5-v6)**: Tim 个人 + 邀请的 15 名城市骨干骑手作为贡献者,手动提交核心 220 条赛段(北京 50 / 上海 30 / 杭州 40 / 深圳 25 / 成都 40 / 广州 20 / 太原 15)
- **中期(v6+)**: 开发轻量化贡献者工具(管理员赛段工具 P0),支持贡献者在小程序/H5 页面上传 GPX 候选 + 选择起终点 + 填元数据
- **长期(v8+)**: 社区成熟后开放"普通用户提交赛段"通道(需要审核)

**赛段详情页"由 @xxx 建立"标注**,让贡献者身份可见,作为社交奖励。

## 理由

1. **赛段的"地方意义"不可算法化**。一条 5 公里上坡道是不是值得成为 KOM 赛段,取决于:它是不是本地骑手公认的"爬坡圣地"?路况怎么样?骑完的仪式感/打卡点在哪?这些是**当地骑行文化的共识**,算法聚类轨迹热度识别不出来。北京西山的妙峰山爬坡路、上海崇明岛环岛、杭州千岛湖 360 公里——这些赛段的地位来自**社群共识**,不是算法投票。

2. **算法聚类会产生大量噪声**。如果按"骑行频次"自动聚类,会聚出大量通勤路段(如地铁站到公司)—— 这些是高频但**骑手不感兴趣**的"伪赛段"。后台还是需要人工审核,反而比纯手工慢。

3. **小众垂直社区的标配玩法**。豆瓣电影编辑 / Wikipedia 条目编辑 / B 站某区 Up 主 —— 所有严肃内容社区都用"身份奖励 + 编辑权限"的模式让核心用户贡献高质量内容。velo 的"赛段编辑员"身份对骑友有荣誉感,比算法冷启动更有人情味。

4. **工作量分摊可行**。220 条赛段 × 平均 30 分钟/条 = 110 小时。一人做要 3-4 周,15 人分摊每人 7-8 小时,一周内完成。而且贡献者本身是本地骑手,比 Tim 更懂本地路况。

5. **信任来自真人**。velo 核心价值是"让骑行者看见彼此",赛段是"看见"的载体之一。"由 @某位本地大神建立"比"系统自动识别"更有信任感和权威感。

## 后果

### 正面
- 赛段质量高,每条都有本地骑手亲手确认
- 贡献者获得身份归属感,成为种子用户和口碑发起人
- 赛段文化沉淀进产品,新用户看到"这条路是本地老 X 建立的"有信任感
- 运营侧可以通过"邀请 @某大神做北京赛段编辑员"建立与本地社群头部骑手的关系(顺便拉用户)

### 负面
- **起量慢**: 初期只有 Tim + 15 位贡献者,覆盖面不如算法
- **地区偏科**: Tim 和贡献者集中的城市覆盖率高,其他城市赛段少
- **依赖人力**: 贡献者流失 = 赛段扩展停滞,需要持续维护社群关系
- **质量参差**: 不同贡献者对"什么算好赛段"标准不同,需要审核统一

### 触发重新评估的条件

v7+(DAU 突破 5 万时)重新评估:
- 是否引入算法**辅助**(聚类候选 + 人工审核确认)—— 注意是辅助不是替代
- 是否开放普通用户提交(降低贡献门槛)
- 是否允许用户"收藏"自己常骑的私人赛段(不公开,只算自己的 PR)

## 违反代价

如果未来 PR 强行开发"轨迹聚类自动生成赛段":

1. **数据污染**: 算法生成大量通勤/重复/方向错误的"伪赛段",用户匹配到没感觉,降低信任
2. **审核成本反超**: 生成 1000 个候选,人工审核删 900 个,比手工创建 100 个还慢
3. **贡献者归属感丢失**: 算法生成的赛段没有"by @xxx"标签,贡献者失去核心激励
4. **产品气质变味**: 从"本地骑手人情味社区"变成"算法推荐的枯燥工具",用户流失

**防御措施**:
- 架构 guide v2 §4.2.4 segments 表不设 `auto_generated` bool 字段,禁止后台自动创建
- v5-v6 spec 明确写"赛段只能 admin 通过 API 创建",算法路径不在路线图
- 贡献者工具开发优先级 P0(见 v5 PRD),保证人力路径顺畅

# ADR-015: 为什么 World Fact、User State、Session、Run、Memory 与 Trace 必须分离

> **一句话核心决策：每类数据只能有一个权威 Owner；World Fact、User State、Planning Session、Agent Run、Long-term Memory、Trace/Eval 与 Compiled Context 必须按权威性和生命周期分离，Context 只是一轮模型调用的编译投影。**

## 1. 状态与适用范围

**Proposed — A1.3，等待 Orchestrator 审查。**

本文只裁决骑前静态规划所需状态的所有权、生命周期和流动边界；它承接 [ADR-013](./013-为什么区分骑前静态规划与骑中实时导航.md) 与 [ADR-014](./014-为什么在线规划采用单一有界主Agent与确定性工作流.md)，不授权实现 Session、Run、Memory、Context Compiler、数据库、API、小程序或 Runtime。

核心不变量是：**World Fact is not Memory**、**Session is working memory**、**Trace is not business truth**、**Context is compiled projection**。

## 2. 当前代码事实

- `User` 已保存用户明确资料，包括 FTP、体重、车型、城市等；这些是一等 User State，不是 Agent Memory。
- `Activity`、`Trackpoint` 与隐私设置保存结构化用户骑行历史；它们不得复制成通用 Memory 文本。
- `RouteBook` / `RouteVersion` 保存用户路线资产与版本化几何，导出任务和制品绑定具体 route/version；它们不是 Session 或 Memory。
- route cognition 已有 `JudgmentRun`、`EvidenceItem`、Research、Concept、Collection、候选和人审后正式关系，并由 writer/write guard 阻止绕过人审；当前没有一等 Claim World Model。
- **JudgmentRun is not online Agent Run**：它记录路线认知的算法、研究或人工审查，不属于在线 Planning Session。
- `RouteExportJob` / `RouteExportArtifact` 是确定性领域副作用任务和工件，不能冒充 Agent Run。
- 当前运行代码不存在目标意义的 Planning Session、Agent Run State、Memory Service、Context Manifest、统一 Map State、Replay 或 VeloBench。
- 当前 `app/agent` 是 DeepSeek 赛段文案生成与 RQ/ORM 草稿写入模块，不是在线规划 Control Plane。
- 当前没有向量数据库或生产长期 Memory。

## 3. 考虑过的方案

### 方案 A：chat transcript 就是 state

把完整聊天历史作为当前状态，恢复时重新让模型解释。实现快，但地图点击、候选选择、pending gate 和 revision 没有确定性真相；同一历史可被不同模型解释成不同状态，因此拒绝。

### 方案 B：通用 agent memory / vector RAG

把世界事实、用户偏好、历史事件和对话摘要统一写入 memory/vector store。检索接口统一，但会产生第二真相源、删除和纠正歧义、敏感值复制及错误事实扩散，因此拒绝该方案，并确立 **no universal agent_state** 与 **no vector database as source of truth**。

### 方案 C：立即建完整 World Model 与六套存储

现在同时设计全部表、TTL、索引、向量检索和 Runtime。边界表面完整，但会把未经 A2/A3/A4 验证的未来形态固化为 schema，也误把逻辑分离等同六套数据库，因此拒绝。

### 方案 D：按 Owner 与 lifecycle 分离

每类状态只有一个权威 Owner；Context 按需引用已授权、带 revision 的最小投影；模型输出只有经 controller 接受才改变状态。选择此方案。

## 4. 正式决策

采用以下边界：

1. Canonical World Fact、User State、Planning Session、Agent Run、Long-term Memory、Trace/Eval 分别拥有独立权威语义。
2. Compiled Context 是一次模型调用的临时投影，不是第七个状态库。
3. 原始对话只是输入与审计证据，不是当前 Session 的唯一权威表示。
4. 模型不能直接写 World Fact、User State 或 Memory；它只可提出受控 proposal。
5. 逻辑分离不要求六套数据库；表、字段、TTL、存储与框架全部延后。

## 5. Ownership 与 Lifecycle 矩阵

| 类别 | 权威 Owner | Scope / 生命周期 | 在线 Agent 权限 | 绝不能冒充 |
|---|---|---|---|---|
| Canonical World Fact | Deterministic Domain + Curation/Human Review | 共享、长期、版本化、带 provenance/freshness | 只读最小 FactPacket | Memory、模型文本 |
| User State | User + Business Domain Services | 账号范围、用户可控 | 读取授权子集；写入走显式业务服务 | 通用 Memory 副本 |
| Planning Session | Deterministic Interaction/Session Service | 一次可恢复的骑行决策 | 只能经 reducer 提议/推进 | chat transcript、Run checkpoint |
| Agent Run | Deterministic Run Controller | 一次 event/resume 触发的有界执行 | 模型仅给 action proposal | Session、Memory、JudgmentRun |
| Long-term Memory v0 | User-controlled Memory Service | 跨 Session、可见、可改、可删、版本化 | 只可 proposal | World Fact、Activity 副本 |
| Trace / Eval | Evaluation & Operations Plane | append-only 运行证据 | 只作为审计/评测输入 | 业务真相、用户 Memory |
| Compiled Context | Context Compiler | 单次 model call 的临时投影 | 读取已授权最小包 | 状态库或真相源 |

## 6. Canonical World Fact

World Fact 包括正式路线/骑行对象、Route/geometry revision refs、Traversal/连接事实、accepted claim/evidence refs，以及带 freshness 与 unknown 的动态状态。

在线 Agent 只能读取最小 FactPacket，不能直写。用户指出公共事实错误时，只能形成 world knowledge proposal，经 curation/review 后才可能改变 canonical world；个人当前解释可先留在 Session。

FactPacket 必须概念上携带对象 ref、revision、freshness、unknown 与 provenance refs；缺少有效动态状态表示 unknown，不等于安全。

## 7. User State

User State 包括明确 Profile、Activity 与结构化历史、saved place/saved route、用户资产，以及已成为一等产品字段的设置和偏好。

写入必须走对应 Profile 或用户资产服务。已有稳定产品字段的数据不得再复制成 Memory；Memory 不是第二套 User 数据库。

精确家庭/常用起点坐标默认不进入模型 Context。模型只看到 opaque ref 与粗粒度 label，例如 `sp_home_01 / 太原站附近`；Domain Tool 在授权范围内解析精确值。

## 8. Planning Session

一个 Session 表示一次用户骑行决策过程，可跨多轮聊天、多个 MapEvent、多次 Run、短暂断线和恢复。

它概念上包含当前 intent、地图锚点/viewport、focused objects、candidate plan refs、selected plan ref、assumptions、unknowns、pending question/confirmation ref 与 session revision。

**one Session can have many Runs**。地图状态只能由 deterministic reducer 根据 MapEvent/MapAction 改变，不能从 Agent 回复文本反推；原始聊天也不是唯一当前状态。

## 9. Agent Run

一个 Run 是由 UserTurn、MapEvent 或 resume 触发的一次有界 Run Controller 执行；一个 Run 只属于一个 Session。

Run 概念上跟踪 base session revision、current step、预算、action proposal refs、tool/observation refs、retry、pending gate 与 stop reason。

**Run binds to Session revision**：Run 从已提交的 Session revision 开始；Session 已变化时，旧 Run 不得提交 stale proposal。Run checkpoint 不是 Session，Run 结束也不会自动变成长期 Memory。

## 10. RidePlanDraft

**RidePlanDraft is session-scoped domain artifact**：它由确定性 Planning Domain 生成、版本化并被 Session 引用，在用户选择前只是 candidate。

它不是公共 World Fact，也不是 Long-term Memory。每次 Plan revision 都使旧 validation 失效；何时持久化为个人资产、选择或真实导出，继续由 A1.4 与后续任务裁决。

## 11. Explicit Memory v0

**Explicit Memory v0** 只允许保存用户主动陈述或明确确认、且尚无稳定一等产品字段的个人偏好或纠正，以及不复制敏感原值的用户资产引用。

Memory 必须 user-visible、user-editable、user-deletable、可版本化并保留来源/确认记录；只在当前任务相关时检索。模型只有 `proposal` 权，具体确认和写入授权延后 A1.4。

禁止保存世界路线事实、完整聊天、Activity 原始副本、精确敏感地点原值、外部网页/UGC、模型自写操作规则或未经用户确认的推断。

## 12. Inferred 与 Episodic 的当前裁决

**Inferred Memory DEFERRED**。推断偏好在 Phase A 只能作为非权威 eval 证据、memory proposal fixture 或 Trace 派生假设；不得自动进入生产 Context、改变 hard constraint 或写入 saved asset。

Episodic history v0 来自结构化 User History 与 Trace，可供确定性摘要查询或 Eval 使用，不自动成为跨 Session Prompt Memory。

只有 explicit memory 合同存在、A3/A4 证明支持/反证/衰减/删除和安全失败、VeloBench 显示可重复价值，并由新 ADR 接受后，才重开 inferred memory。

## 13. Correction 与 Procedural Learning

个人语义纠正先影响 Session；用户明确要求长期记住时，才可提议 explicit personal memory。

公共世界纠正只能生成 curation proposal，不能由在线 Agent 直写 World Fact。

系统从失败中学习必须走 `Trace failure → human/eval triage → versioned tool/prompt/policy/code change → regression`；线上 Agent 不得自改 Prompt/Policy 并称为 procedural memory。

## 14. Trace / Eval

Trace 记录 Context Manifest、model proposals、tool/result refs、state deltas、预算、stop reason、latency/cost、grader 与 replay refs。

Trace 是 append-only evidence，不是 World/User/Session 真相，也不是 Memory。Replay 只能重放确定性观察和状态演进，不得重复真实副作用。

## 15. Compiled Context

Context Compiler 每次 model call 按需组合 policy/playbook、授权 User State、已提交 Session snapshot、相关 Explicit Memory、最小 World FactPacket 与 Plan summary。

Context Manifest 属于 Trace，概念上记录 source refs/revisions、omitted sections、policy/tool versions 与 token summary。默认不加载完整聊天、全部 Activity、Evidence、世界对象或 Memory。

模型输出不是新真相；只有经 ADR-014 的 controller/gates 接受后，才可能形成状态变更。

## 16. Revision 与并发不变量

- Run binds to base Session revision；Session changes invalidate stale Run commit。
- Plan revision invalidates old validation。
- World FactPacket carries revision/freshness/unknown。
- Context Manifest records source refs and revisions。
- 中断恢复不得重置已消耗预算或重复副作用。

具体字段名、错误码与 optimistic concurrency schema 延后 A2。

## 17. 与其他决策和任务的关系

- ADR-013 回答“允许规划什么”；ADR-014 回答“谁控制一次在线 Run”；ADR-015 回答“状态和记忆属于谁”。
- A1.4 决定 Capability、Approval、Side Effect 与 Memory write authorization。
- A1.5 决定旧 `app/agent` 命名迁移，不把现有文案模块冒充 Runtime。
- A2 定义 ID、revision、字段和 JSON Schema；A3/A4 验证 inferred memory、安全失败与 replay。

## 18. Trade-off 与后果

我们接受更多显式边界、引用和版本管理成本，换取单一真相源、隐私可控、stale 写入可拒绝、Trace 可审计以及模型/框架可替换。

代价是 Context 需要编译、服务间需要稳定 refs，且早期不能靠一个 JSON blob 快速堆功能；但这避免错误 Memory 变成公共事实或过期 Run 覆盖新 Session。

## 19. 非目标

- 不实现 Session、Run、Memory、Context Compiler、Replay 或 VeloBench。
- 不设计数据库表、JSON Schema、精确 TTL、缓存或检索算法。
- 不选择 Postgres/Redis/向量库、embedding、Python/TypeScript Runtime、OpenAI Agents SDK 或 LangGraph。
- 不修改 API、小程序、Provider、RouteBook、export、migration、测试或生产行为。
- 不决定 A1.4 approval taxonomy，不开始 A1.4/A1.5/A2，不调用真实 Provider，不导出、不部署。

## 20. Reopen triggers

- A2 合同无法在不合并某两类权威状态的情况下表达真实恢复或并发语义。
- A3/A4 的可重复案例证明当前 Context/Memory 边界无法安全完成核心骑前规划。
- 生产隐私、删除、法规或真实故障证明 opaque ref 与显式 Memory v0 不足。
- 新 ADR 以可复查证据接受 inferred memory、不同 ownership 或存储边界。

# ADR-010: 为什么不做实时导航,跳转高德完成

## 状态
accepted (2026-04-22)

## 上下文

velo 做"骑行平台"的边界问题: **要不要做实时骑行导航**?

骑行用户的完整场景链路:
1. **骑行前**: 规划路线 / 看天气 / 查找赛段
2. **骑行中**: 实时导航 / 语音播报 / 路径偏离重规划 / 实时速度 / 心率
3. **骑行后**: 数据分析 / 社交分享 / 成绩查看

Strava / Komoot / 黑鸟单车 / 行者骑行 都覆盖全链路(含实时导航)。velo v0-v4 只做了 "骑行后"(GPX 上传 → 解析 → 排行),"骑行前"(路线规划)和"骑行中"(实时导航)都是空白。

v5 规划期决策: **velo 要不要补全"骑行中"这一段**?

## 决策

velo **永远不做实时骑行导航**。

- "骑行前"规划阶段: velo 生成 GPX 路线文件
- "骑行中"导航阶段: 用户通过 GPX 导入高德 / 百度地图 / 码表设备完成实时导航
- "骑行后"数据阶段: velo 接收 GPX(码表同步或手动上传)继续分析

velo 的产品边界是 **"骑行前的规划辅助 + 骑行后的回顾社交"**,不是一站式 app。

## 理由

1. **实时导航是极重的工程投入,velo 不可能做得比专业地图好**。实时导航需要: 全国路网数据(地图厂商才有) + 实时路况(需要数据合作) + 语音播报(TTS 技术) + 路径偏离重规划算法 + 离线地图缓存 + 地图渲染性能优化。每一项都是巨大投入,velo 做几年也比不过高德。

2. **中国地图服务商已经做到极致**。高德骑行导航覆盖全国,免费,支持微信小程序跳转调起。百度地图同样。用户已经习惯这个流程:在规划 app 里看,在地图 app 里导航。**不要跟用户习惯对着干**。

3. **用户心智上两个场景是分开的**。调研中严肃骑手的真实使用流程:
   - "规划 + 查成绩":用专业骑行 app(Strava / velo)
   - "导航":用高德 / 码表(Garmin / iGPSport)
   
   这两个场景用户**愿意切换 app**,因为各自专精。velo 想"一站式"反而让用户觉得"哪样都不专业"。

4. **velo 的价值在"骑行前"和"骑行后"**。"骑行前"的价值: 发现路线 / 看他人骑行数据做参考 / 了解赛段难度 / 社交"周六有人要一起吗"。"骑行后"的价值: 数据分析 / 成绩对比 / 分享 / 荣誉。这两端都是**社交 + 数据深度分析**的场景,高德做不了,这是 velo 的护城河。

5. **专注才能精深**。团队 3 人学生,战略聚焦最重要。每花 1 人月在导航上,就少 1 人月在社交/数据分析上。放弃导航 = 把资源全部押在 velo 能做到极致的地方。

6. **严肃骑手用码表不看手机导航**。velo 目标用户("一线城市严肃公路车骑手")通常有专业码表(Garmin / iGPSport / 黑鸟),码表直接显示导航 + 数据。手机导航是"休闲骑行"场景,不是 velo 的主场。

## 后果

### 正面
- 工程焦点聚焦,不在导航功能上浪费资源
- 产品定位清晰:"velo 专攻骑行前规划 + 骑行后社交"
- 用户心智不混乱,不期待 velo 做实时导航功能

### 负面
- 部分休闲骑行用户可能期待 "一站式" 体验,选择离开(但他们也不是 velo 的目标用户)
- "骑行中" 完全是空白,用户感知上可能觉得 velo "只是个数据 app"(需要通过 "骑行前规划 + 骑行后社交" 的强体验补偿)
- 与 Strava / Komoot 等竞品功能对比时,被指 "缺少导航"(需要 PR 叙事主动解释:velo 不是 Strava,是 Letterboxd + 懂球帝 + 骑友匹配)

### 触发重新评估的条件

**近乎永不重新评估**。以下极端场景才考虑:
- 高德/百度导航 API 突然开始收费(概率极低)
- 中国政策变化禁止第三方地图调起(概率极低)
- velo 转向"休闲骑行"用户群(战略转型,不是战术调整)

## 实现方式(骑行前 → 骑行中衔接)

velo 不做实时导航,但要**丝滑地把用户送到高德导航**:

1. velo 小程序"路线详情"页,用户看路线 + 赛段 + 其他人骑行数据
2. 用户点 "在高德打开" 按钮
3. 小程序用 `wx.openEmbeddedMiniProgram` 或 URL scheme `amapuri://openFeature?...` 跳转高德
4. 高德接收 GPX / 坐标列表,进入骑行导航模式
5. 用户骑完后,码表/手机记录 GPX
6. 回 velo 上传 GPX → 继续数据分析

**关键**: velo 提供 GPX 导出 + 高德深度链接的"衔接能力",高德提供"实时导航"的本职。

## 违反代价

如果未来 PR 在 velo 开发"实时导航":

1. **资源黑洞**: 导航是 10 人月起的工程量,team 3 人无法承担
2. **用户体验降级**: velo 的导航一定比高德差 10 倍,用户感知"velo 不专业"
3. **战略偏移**: 资源被拉去做导航,社交 / 数据分析的护城河挖不深,最终被 Strava 或 outbase 赶上
4. **数据合规风险**: 实时导航涉及实时位置上传 + 路况数据,合规成本极高

**防御措施**:
- PRD 长期不包含导航功能(v8+ 路线图明确排除)
- 任何涉及"实时 GPS 展示 / 路径重规划 / 语音播报"的需求,直接归为 "不做",不纳入候选池
- 架构 guide v2 §1.2 明确"不包含实时导航"

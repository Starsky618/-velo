## 1. 这期解决谁的什么问题(用户故事)

周四晚上,Starsky 在太原骑友群发一张约骑分享卡:「周六早上天龙山西线,已经 6 个人了」。老张点进来,看到路线路书、出发时间和几个认识的名字,点了参加。周六骑完,晚上老张在群里看到第一个交卷的人发的成绩卡(均速、爬升、「已交卷 1/6,5 个人的卷子还空着」),点开卡落在战报页,自己那格是灰的——他从码表 app 导出文件发到微信,在 velo 里两步选入,五秒内开奖:数据逐项浮现、海拔曲线画出来,最后拿到一张比码表截图体面的卡,顺手发回群里。战报页上他的格子亮了,集体合计往上跳。

第一个交卷的人不吃亏(demo 已验证,Tim 过审):开奖 + 体面的卡 + 「战报由你开张」首发权 + 卡片即催缴令,四层回报在 N=1 全量成立。

## 2. 验收标准(每条二元可判)

- 钟声(D-005):一场约骑中,至少一名半生人完成全链——分享卡触达 → 自主进入 → 报名 → 到场骑完 → 数据回流留痕,五环节零代办
- 上传体验三拍:选文件(微信聊天记录入口)→ 开奖(数据逐项揭晓)→ 成绩卡(可微信原生分享,带「已交卷 m/n」钩子)
- 时间窗自动关联:约骑当天参与者上传的活动自动挂到该约骑,战报页可见
- 战报页:集体合计 + 照片墙 + 每人一格(按交卷点亮,无名次列),仅经分享卡/约骑入口进入
- 天龙山西线在生产环境有完整路书内容(route skill 产物灌入)
- 生产部署核实:约骑全模块在线上真用走通(commit ≠ ship)

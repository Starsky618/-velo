# Phase-N PRD 模板

> 本文件填补 architect skill 引用的悬空指针(它一直引用 docs/prd/TEMPLATE.md 但此前不存在——2026-06-10 审计发现并补上)。每期开工复制本模板为 phase-N-prd.md。

## 1. 这期解决谁的什么问题(用户故事)

具体用户的具体一天,能演成小电影。不是「XX 页面+XX 接口」。

## 2. 验收标准

每条可二元判定。骑友视角写,不用技术词。

## 3. 明确不做(Out of Scope)

被讨论过但否决的项 + 一句为什么(否决是资产)。

## 4. 数据回看(2026-06-10 新增必填 / ship 后 1 问)

- 这期功能 ship 后,看什么数字判断它有没有被用 / 用得好不好:(具体 SQL / 日志 grep / 看板位置)
- 回看日期:(具体到日,写进日历;到期由 recheck_scanner 点名)
- 点火/熄火判据:什么数字出现说明这功能成了 / 什么数字说明该砍(可证伪,参照 strategy 决策库 D-003 风格)

## 5. 与核心反馈环的关系

这期投入打在「骑车→上传→解析→排行→激励→继续骑」环上的哪个节点?为什么当前最脆弱的是这个节点(证据,不是感觉)?

## 0. velo 身份(一段话)

velo = 中国一线城市严肃公路车骑手的身份图谱 + 社交网络。

WeChat 小程序 + FastAPI/PostgreSQL 后端。当前 v5 阶段(2026 Q2-Q3)。目标 sustainable 小而美,不追独角兽。

---

## 1. INVARIANTS(永不违反的产品层不变式)

以下 6 条任何提议违反都必须 REJECT,并 escalate 到 Tim 讨论。不得自行绕过。

### INV-P01:只做公路车垂直
- 不扩展到跑步、徒步、游泳、登山、综合运动、铁三、室内健身
- gravel 作为公路车边缘延伸可支持,但 v5-v6 不是主画像
- 山地车 DH/XC 玩家不是 velo 用户

> **论证**:综合化扩张是中国骑行 app 前辈最常见的死法。见 `docs/competitive-analysis/行者-黑鸟-骑记-失败模式.md`。

### INV-P02:不做硬件
- 永远不自制码表、头盔、骑行服、整车、功率计、轮组
- velo 是骑手身份中立平台,所有硬件厂家都是数据源或合作伙伴,不是竞品
- 例外:velo 品牌周边(车衣、水壶、贴纸)作为身份符号,v8+ 可考虑

> **论证**:骑记被小米收购后被拉去做硬件 app 业务边缘化,行者三驾马车战略失败。见 ADR-007 + 竞品分析。

### INV-P03:不做实时骑行导航
- 不做路径规划算法、语音播报、路径重规划、实时路况
- velo 提供 GPX 导出 + 跳转高德/百度完成导航
- 可以显示静态轨迹、坡度剖面,但不做导航行为

> **论证**:路径规划低频场景 + 中国高德/百度已做到极致 + velo 3 人团队做不动。见 ADR-010 + `competitive-analysis/komoot-对标.md`。

### INV-P04:不做 feature 订阅
- 不做"付费解锁功率曲线""付费解锁赛段历史"等 Strava Premium 式商业化
- 所有 Strava Premium 付费墙后的高级分析功能,velo 全部免费
- v7+ 商业化走 outcome-based(精英社群、训练营、装备联运、赛事合作)

> **论证**:中国用户不为 feature 订阅(行者 PRO 已证明)。见 ADR-009 + `velo-strategy.md §4`。

### INV-P05:不做装备电商
- v5-v7 不做装备电商(无库存、无物流、无售后)
- v8+ 可考虑"内容导购"(基于骑行数据推荐装备,跳转电商厂家,CPS 分成)
- velo 不自己发货、不持有库存

> **论证**:行者三驾马车(软件+硬件+电商)战略失败。电商做不过京东/天猫。

### INV-P06:不做室内虚拟骑行
- 不做类似 Zwift 的室内虚拟训练平台、虚拟赛道、电竞骑行
- velo 核心价值在"真实户外骑行的数据沉淀和社交"
- 室内训练场景引导用户使用 Zwift / Onelap 等专业工具

## 2. 用户画像优先级

### P1-MAIN:严肃公路车骑手(核心画像,60-70% 资源)

**画像定义(精确)**:
- 年龄 25-40 岁
- 生活在一线/新一线城市(北京/上海/杭州/深圳/成都/广州/武汉/西安/南京/苏州)
- 拥有公路车,车价 > 1 万人民币
- 每周骑 2-4 次,月均 300-800 公里
- FTP > 180W(或骑行水平等效)
- 有 Strava 账号但用得痛苦 / 或使用国产码表(iGPSport / Magene / Garmin)

**5 个子画像**(见 `velo-product-spec.md §1` 或 `velo-mental-model.md`):
- A 都市独行者(50%):王哲式
- B Club 活跃分子(25%):张红式
- C 新晋严肃骑手(15%):李明式
- D 资深 KOL 老炮(5%,战略价值高):老周式
- E 女性骑手(5%,战略价值高):小美式

### P2-SUB:休闲骑行族 / 风景党(UGC 贡献者,非稀释)

- 骑行频率低(每 2-4 周一次),距离 30-50 公里
- 社交主场在小红书、抖音
- 骑行目的是风景 / 拍照 / 体验
- **在 velo 的定位**:UGC 贡献者(出片路线、风景打卡),**不主画像化**
- v5-v6 不主动服务,v6 后在"探索其他城市"入口给他们空间

### P3-NETWORK:生态节点(运营关系,非产品画像)

- Club 领队 / 车队长(每城 3-10 个头部 club)
- 车店老板(本地骑行文化的温床)
- 赛事组织方(全国每年数千个骑行赛事)
- 骑行品牌 BD(装备品牌、活动品牌)
- **在 velo 的定位**:运营连接对象,不是产品的消费用户

### NON-USER:明确不服务的人群

- 共享单车用户、城市通勤族
- 儿童自行车家长、电助力车用户
- 山地车 DH/XC 玩家(独立生态)
- 铁人三项运动员(需跑步游泳整合)
- 室内骑行党(Zwift 用户)
- 只骑过 1-2 次完全不严肃的轻度尝试者

> **决策使用**:任何功能提议首先问"对 P1 有直接价值吗"。只对 P2/P3 有价值 → 降级为外壳层/延期/砍。对 NON-USER 有价值而对 P1 无价值 → REJECT。

## 3. 产品根本原则

### 社交:工具 = 60:40

所有产品决策在冲突时,**社交优先**。

具体体现:
- 首页是动态 feed,不是个人数据摘要
- 赛段页是社区(排行榜 + 笔记 + 实景 + 讨论),不只是排行榜
- 个人主页是身份表达(4 最爱赛段 + 热图 + 贡献内容),不只是统计报表
- 通知优先推"有人和你骑了同一段",不优先推"你本周骑了多少"

### 四层类比分工

讨论 velo 产品形态时,四元类比各司其职,不混用:

- **Letterboxd = 产品运作逻辑**(垂直身份图谱 / 4 最爱 / list / 小而美独立)
- **懂球帝 = 社交逻辑**(垂直深度 / 按城市车型主题分圈)
- **Strava = 硬核数据逻辑**(赛段 / PR / KOM / 功率分析)
- **小红书 / 抖音 / 微信群 = 内容素材来源**(UGC 原料,不是产品模板)

## 4. 内核 + 外壳架构

velo 有两层结构,不能颠倒:

### 内核(本地骑手工具,v5-v6 核心):
- 主 feed:关注骑友的动态
- 本城市赛段和排行榜
- 本地路线理解与骑行身份
- 个人身份图谱
- 骑友推荐(本城市 + 常骑重合)

### 外壳(骑行文化内容,v6-v7 渐进引入):
- "探索其他城市"入口(v6 加)
- 跨城市热门赛段 / 精选路书
- 城市骑行文化故事
- 风景打卡路线

**决策规则**:用户默认看内核内容,外壳需要主动点击进入。v5 不做外壳;v6 加入口;v7 外壳内容在主 feed 有 20% 占比。不可倒置。

## 5. 产品决策规则

### D-P01:新功能评估的强制 checklist

任何功能提议,按顺序回答:

1. 对 P1 主画像有直接价值吗? 否 → DEFER 或 REJECT
2. 违反 INV-P01 到 INV-P06 吗? 是 → REJECT
3. 是强化社交还是强化工具? 只强化工具 → 深度质疑(已 40% 不应再加)
4. 当期 scope 内吗? 否 → DEFER 到对应版本
5. 有"不做"也能解决的方案吗? 有 → 优先不做

**完整 10 问框架见 `velo-mental-model.md §功能必要性评估`**。

### D-P02:扩展运动类型的提议

任何扩展到非公路车运动的提议(跑步、徒步、游泳、综合运动、山地 DH、铁三等)→ **立即 REJECT**。

这会触发 PRD 修订讨论,不是普通功能决策。

### D-P03:商业化提议

- v1-v6 阶段:任何付费 / 订阅 / 广告的提议 → REJECT(velo 此阶段全免费)
- v7+ 阶段:按 outcome-based 四路径评估(精英社群 / 训练营 / 装备联运 / 赛事合作)
- 永不:feature 订阅(INV-P04)

### D-P04:做实时导航 / 路径规划的提议

→ **REJECT**,跳转高德完成。

理由:ADR-010。

### D-P05:做硬件 / 装备电商的提议

→ **REJECT**。velo 保持硬件中立。

理由:INV-P02 + INV-P05 + ADR-007。

### D-P06:原生 app 提议

- v5-v6 阶段:REJECT,只做小程序
- v7+ 阶段:根据用户数据评估。启动原生 app 的触发条件:
  - 50% 以上活跃用户明确要求后台 GPS 记录
  - DAU 突破 1 万(小程序承载力边界)
  - 蓝牙码表连接成为高频付费意愿点

理由:ADR-006。

### D-P07:AI / Agent 层在产品中的位置

- v1-v6 阶段:velo 主产品**不依赖 AI 做差异化**
- v7+ 阶段:agent 层作为独立模块,与主 SaaS 通过薄接口连接
- agent 是**规模化杠杆**(1 个教练服务 10 人 → AI 辅助服务 500 人),不是产品核心差异化
- 用户关掉 agent,velo 仍是完整产品

理由:ADR-009。

### D-P08:用户数据和隐私

- 默认最谨慎:涉及"被陌生人看到"的功能默认关闭,用户主动开启
- 骑友推荐不显示真实位置(只显示"他也常骑西山")
- 新注册用户 1 个月内不进入推荐系统
- 用户可退出推荐、删除内容、匿名化
- 三层身份:完全匿名(默认)/ 昵称公开 / 实名认证(贡献者)

### D-P09:社交机制的双层(私圈优先,公共层延后)

- 本条关于俱乐部、邀请制和本市约骑广场的具体解法已被 2026-07-28 当前覆盖结论暂停。
- 当前只保留“需要密度的社交机制不得冒充首个用户价值”这一约束，不保留约骑前端预埋。
- 未来若有真实用户场景和密度证据，再重新定义社交机制，不从保留的后端兼容面直接恢复页面。

### D-P10:UGC 三来源策略

所有赛段介绍 / 路书 / 笔记来源必须在以下三类之一:

- **来源 1**:Tim + 贡献者原创(质量最高,v5 主力)
- **来源 2**:AI 从公开数据蒸馏 + Tim 人工审核改写(扩展长尾)
- **来源 3**:用户自发上传(v5 架构预留,v6 激活)

**硬边界**:
- 来源 2 的 AI 不直接抄袭具体小红书/抖音帖子,只从大量公开数据提取共性
- 来源 2 发布必须 Tim 亲自审核改写后发布,不直接发 AI 原始输出
- 来源 2 标注"由 @xxx 整理",不冒充原创骑手

## 6. 活人感硬标准(RUBRIC-CONTENT)

所有 UGC / AI 生成内容 / 产品文案,必须满足以下至少 3 条,否则 REJECT:

1. **有具体的人、店、时间、细节**(不是泛泛陈述)
   - ✅ "老王家刀削面走这段必吃"
   - ❌ "附近有推荐餐饮"

2. **有对错、好坏、避雷建议**(不是只夸不损)
   - ✅ "这段别在下午 2 点骑,因为路面晒得像火"
   - ❌ "这段路很好骑"

3. **有本地黑话或圈内梗**(不是标准化语言)
   - ✅ "天龙山逆天陡坡""KOM 王座""爬坡虐腿"
   - ❌ "具有挑战性的爬坡路段"

4. **有主观感受**(不是客观描述)
   - ✅ "骑完这段腿发抖但爽到爆"
   - ❌ "距离 15 公里海拔上升 800 米"

**审核判定**:
- 满足 4/4 条 → 直接发布
- 满足 3/4 条 → 发布
- 满足 2/4 条 → RETURN 要求改写
- 满足 0-1/4 条 → REJECT

**深层心法见 `velo-mental-model.md §活人感的深层心法`**。

## 7. 写作调性规则

### 禁止词(产品文案、UI 措辞、运营内容)

- "超震撼""最强""极致""完美" → 销售话术,违反克制原则
- "用户体验""价值主张""赋能""打造" → B 端官腔,不像真人说话
- "解锁""尊享""升级" → Strava Premium 式的付费引导词
- "所有运动爱好者""综合健身""全方位" → 违反垂直定位
- "AI 智能"开头 → 除非真是 agent 层功能,否则不提 AI

### 推荐调性

参考:
- Letterboxd 的"passionate / earnest / old-internet-feeling"
- V2EX 的老派程序员克制
- 即刻早期的"圈子调性对"

避免:
- 小红书精致种草感
- 大众点评冷数据感
- 咕咚综合平台感
- 行者商业驱动感

### 文案原则

- 像真人骑手说话,不像公关稿
- 数据维度可以深(功率/心率/坡度),但语言要亲切
- 不堆砌 emoji
- 不用"您"(用"你",骑友平辈感)

## 8. 当前版本 scope(v5,2026 Q2-Q3)

### v5 DO(明确要做):

- 功率曲线 + 赛段历史对比(PRD 4.1 遗留项,免费)
- 4 最爱赛段(个人主页,Letterboxd 式身份)
- 个人骑行热图
- AI 批量生成赛段介绍(Tim 审核改写 + RAG 独立模块)
- 管理员赛段工具 P0
- 轻社交 spec 定稿(实现延后 v6)
- 赛段详情页基础版(排行榜 + 坡度剖面 + 地图 + 介绍 + 贡献者标注)
- 文档体系收尾(PRD + ADR + 本 agent-rules)

### v5 DON'T(明确不做,延 v6+):

- 重社交(约骑 event / 私聊 / feed 流)
- 商业化(付费墙 / 订阅 / 广告)
- Agent 层
- 原生 app
- 路书(list)机制
- 赛段笔记 / 实景墙 UGC 完整版(只架构预留)
- year in ride(v6 底或简化月度版)
- 俱乐部管理工具
- 即刻式轻社区
- 数据同步网关
- "探索其他城市"入口
- 运动扩展(永远不做)

### v5 scope 管理硬约束

- 任务数 ≤ 6(违反 = 复杂度失控,参 CLAUDE.md)
- Spec ≤ 800 行
- v5 结束前必须处理完 P1 tech-debt,不带进 v6

## 10. 给 Agent 的最终原则

1. **宁可停下询问,不要错误推进**。说"我不确定"比说错好,Tim 尊重诚实不尊重自信的错误。

2. **引用 ID 是硬要求**。判断时必须引用 INV / D-P / RUBRIC / MENTAL 等 ID,让人类可追溯。不允许"我觉得"。

3. **规则没覆盖时加载 mental-model**。规则层覆盖 90% 日常决策。遇到新场景或模糊判断,加载 `velo-mental-model.md` 用 10 问框架思考。

4. **保持 velo 调性**。所有产品输出(代码注释、文档、UGC、UI 文案)符合 velo 品牌气质——严肃、活生生、垂直、本地、独立、克制、硬核但亲民。

5. **永远问:Tim 自己会用吗?Tim 会自豪地和骑友讲吗?** 不确定时用这两个问题回测。
